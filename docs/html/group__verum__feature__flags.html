#define VERUM_STANDARD_FIPS_140_3_DEF

#include <define.h>

Enable FIPS 140-3 compliance mode.

When defined, activates the full set of controls mandated by FIPS 140-3 (ISO/IEC 19790:2012) for a software cryptographic module. The following requirements are enforced:

[TODO]

  • Power-on self-tests (Section 9.5). On every cold initialisation the module executes the Known-Answer Tests for each enabled primitive (AEAD128, Hash256, XOF128). A failure places the module in a permanent error state from which no cryptographic output is produced and VERUM_FAULT_HANDLER is invoked. [TODO]
  • Conditional self-tests (Section 9.6). A pair-wise consistency check is performed on each key prior to its first use in an encrypt or decrypt operation. If the check fails the key is rejected and VERUM_FAULT_HANDLER is invoked. [DONE]
  • Zeroization of sensitive data (Section 9.7). All cryptographic variables — key copies, the Ascon permutation state, authentication tag intermediates, and XOF squeeze buffers — are overwritten with zeroes before the enclosing function returns. Stores are issued through VERUM_ATTR_VOLATILE pointers to prevent the optimiser from eliding them as dead stores.

Enabling this flag increases code size, startup latency, and per-call overhead. VERUM_FAULT_HANDLER must be defined when this flag is active.
